    THE IMPORTANT DETAILS
    Clear signals. Clear boundaries.
    Does a low-risk score mean a token is safe?
    No. Scores summarize selected heuristics. Hidden contract logic, liquidity changes, proxies and incomplete history can evade these checks. Review the flags, coverage and limitations returned with each result.
    Is Block-0 detection guaranteed to cover launch?
    No. Solana scans bounded RPC-available history; Base scans a bounded block range. Results explicitly report that launch is unverified. Same-slot activity, Jito tips and common funders are evidence to investigate, not proof of a cabal.
    Where does my data go?
    Requested addresses and transaction hashes go to your configured blockchain RPC providers (with automatic failover to publicnode.com if the default public RPC is rate-limited) and read-only enrichment endpoints (RugCheck for Solana holder fallback, honeypot.is for Base tax simulation; browser scans also query DexScreener and GoPlus directly). In the CLI/MCP server, set CABAL_RADAR_NO_FAILOVER=1 or CABAL_RADAR_NO_ENRICHMENT=1 to disable failover or third-party enrichment. There is no first-party telemetry or central licensing backend, and browser wallet connection is only requested if you click a Base checkout button.
    How is Pro activation protected?
    The client checks a successful mainnet receipt and minimum payment to the official recipient. A deterministic HMAC binds the saved license to a local machine label and receipt. This detects accidental edits; it is not tamper-proof DRM and cannot prevent reuse of public receipts on other machines.
    Is the optional edge API a full x402 payment gateway?
    It provides a custom receipt-based HTTP 402 flow. It does not implement the x402 exact authorization and settlement protocol or prevent receipt replay. Local MCP and CLI use require no edge deployment.
